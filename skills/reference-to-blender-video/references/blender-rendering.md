# 建模、运镜和批量渲染

## 建模与正交视图

- 将尺寸、附肢根部站位和相对高度参数化。先比较整体剪影，不靠材质遮掩比例问题。
- 用三台正交相机观察同一中性姿态。俯视与侧视需要统一图上总长或标明比例尺，正视则检查左右跨度与高度。不要旋转或缩放模型来迎合不同视图。
- 部件材质差异、装甲间隙和连接关系比均匀堆砌小零件更能形成可信层次。将成千上万个铆钉合并网格或实例化，避免逐对象操作拖慢动画。
- 草模、比例修订、精修保存为可区分的版本，保留被替代的阶段图用于复盘。

## 动画不破坏模型

根对象负责整体飞行，各附肢由子级枢轴控制。若细节已经批量合并，使用权重或 Hook 等方式让细节跟随所属部件，避免翼片动了而铆钉留在原地。

炮口火光随炮口走，离开炮口后的示踪轨迹、烟雾应在世界空间继续运动。使用短时池化对象，分别控制出现、位移与消失，避免每帧无上限地创建对象。

## 镜头检查

相机路径相对主体根对象定义，观察点使用主体局部坐标转到世界空间。不要只把相机朝向一个不随飞船移动的静态点。

检查实际求值后的网格，包括摆翼和尾部附肢。可用相机投影得到标准化屏幕坐标，范围应位于画面内并保留适合镜头意图的边距。AABB 可用于保守碰撞筛查；包围盒投影超界不必然表示真实轮廓被裁，需用实际网格复核。

查看开始、中间、结尾之外的运动极值与动作时点。新机位可能暴露单张静帧未覆盖的岩壁底部、地表边缘或云层接缝。应补充布景，而不是仅检查相机没有穿入物体。

## 小成本预览

先渲染少量代表帧，再输出能看清完整运镜的低成本动画。一个可用起点是 480×270、12fps、低采样；这是预览配置，不能在最终交付时仅修改容器帧率冒充 24fps。

将 `preview/`、`pilot/`、`final/` 分开。试帧可能采样源帧 1、49、121，却从文件 0001 编号；若误放进 final，续渲染时会把这些错误源帧当作最终前几帧。

## 批处理与恢复

为每个镜头记录以下内容，路径相对项目根目录：

```json
{
  "scene": "Scene",
  "width": 1280,
  "height": 720,
  "fps": 24,
  "shots": [
    {"id": "A", "camera": "Camera_A", "source_start": 1, "source_end": 240, "seconds": 10},
    {"id": "B", "camera": "Camera_B", "source_start": 1, "source_end": 120, "seconds": 5},
    {"id": "C", "camera": "Camera_C", "source_start": 61, "source_end": 180, "seconds": 5}
  ]
}
```

渲染时明确设置场景、相机、源帧、分辨率、采样、运动模糊和输出格式。每帧完成后保存源帧与文件名映射。续渲染需要验证配置指纹、图片尺寸及可解码性；设置改变后使用新输出目录。

```python
scene.camera = bpy.data.objects[shot["camera"]]
for index, source_frame in enumerate(range(shot["source_start"], shot["source_end"] + 1), 1):
    scene.frame_set(source_frame)
    scene.render.filepath = str(frame_dir / f"frame_{index:04d}.png")
    bpy.ops.render.render(write_still=True)
```

生产脚本应在上述循环外补齐配置验证、目录与错误处理。渲染异常时保存日志和已完成帧，修复原因后恢复，不以成功状态跳过失败镜头。

## 工具版本与平台

本例运行于 Blender 5.1，使用 Eevee 48 次采样、体积 32 次采样、0.3 快门运动模糊。它是已跑通的实例，不是其他硬件、材质和 Blender 版本的质量保证。先检查本地 API：Blender 5 的合成节点组配置与一些旧版教程不同。

部分桌面环境需要真实图形服务才能启动后台渲染；启动崩溃先检查日志与环境权限，不要把未启动误报为无 GPU，也不要擅自改用户的全局配置。

FFmpeg 使用明确的输入帧率。常见交付可选 H.264、yuv420p、faststart，并保持各剪辑段分辨率、帧率、色彩标记和音频采样率一致。最终 `.blend` 的默认渲染配置也应与交付说明一致。
