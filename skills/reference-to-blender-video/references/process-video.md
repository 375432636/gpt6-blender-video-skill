# 制作过程视频的证据与剪辑

## 保存真实过程

每个阶段记录图片或视频、素材性质、原始指令、反馈、修订结果和可复用提示词。后续画出的概念图不是最初截图；实际渲染也不是操作录屏。没有录屏时用已保存的阶段图复盘，不伪造界面操作。

剪辑清单应记录每段的时间、标题、画面、画面标签、提示词、解说和新增镜头路径。路径相对项目根目录，避免把私人主目录写进分享文件。

## 本案例的 95 秒结构

| 时段 | 内容 |
| --- | --- |
| 0–5 秒 | 成片片段与标题 |
| 5–15 秒 | 参考整理后的外观设定 |
| 15–26 秒 | 概念三视图 |
| 26–32 秒 | 内部与部件拆解 |
| 32–44 秒 | V1、V2 实际建模预览 |
| 44–56 秒 | 比例反馈与 V3 对照 |
| 56–64 秒 | 模型与环境细节 |
| 64–75 秒 | 运镜预览与正式首帧 |
| 75–85 秒 | 10 秒新主镜头 |
| 85–90 秒 | 5 秒高位镜头 |
| 90–95 秒 | 5 秒低位镜头 |

此时间表是案例。根据素材量、解说语速和用户目标调整，不强制所有视频为 95 秒。用户要求增加的两个 5 秒镜头应各有完整播放时长，不能仅各闪过一帧。

## 画面与音频

阶段图保留全貌，旁边放精炼提示词，底部标记阶段与版本。长提示词放文档，画面只保留能读完的部分。概念图、实际模型三视图、工作预览、最终渲染用准确标签区分。

字体与字幕按最终分辨率检查。没有 FFmpeg drawtext 时，可用排版工具输出透明文字层再 overlay；不要为此重画主体图。FFmpeg 编译功能应以本机 `-filters` 检查为准。

解说长度不得超过片段可用时间。先调整句子，必要时小幅调速，并检查术语发音和句尾。背景音轻于说话，配乐或音效记录来源；可以使用自行合成的声音。可同时交付外置 SRT 和文稿，避免画面内过多文字抢占阶段图。

## 输出与检查

将各段统一到实际交付分辨率、帧率、像素格式、音频采样率后拼接。检查最终编码文件的帧数和时长，不能只读剪辑清单中的预期值。抽取各段中间与边界附近的帧，检查文字、黑帧、重复画面和镜头衔接；检查音轨存在且没有削波。

保留独立镜头与带解说的制作视频，让用户可以再次剪辑。将过程图片集中整理，并提供图片索引和提示词文档。

## 描述文案

描述至少包含：成果简述、工作步骤、视频规格、仓库 URL、skill 直达 URL。可加入章节时间。用户未指定视频平台时，写入仓库说明和一份独立文案即可；按需把相同链接嵌入 MP4 元数据，播放器是否显示由播放器决定。

公开版本只包含必要交付。先完成本地视频与 skill 检查，再推送。推送后核对公开可见性、提交、媒体文件与链接，避免文案仍引用本地文件或待创建地址。
